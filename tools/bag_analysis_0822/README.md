## 1. 정지 교착 — "장애물이 앞에 있으면 overtake 가 뜨는데 출발을 안 한다"

**게이트가 닫혀 있었다. 5b59743 의 수정은 정확했지만 게이트가 이 케이스를 통째로
비켜 갔다.**

정지 구간 4개 = 191.8 s (두 백 375.9 s 의 51 %), 전부 사람이 차를 옮겨서 풀었다.

| 백 | 구간 | 길이 | 자차 s | 명령 0 | 계획 선두속도 중앙 | evade_committed |
|---|---|---|---|---|---|---|
| 143207 | 1.3-20.4 | 19.1 s | 35.5 | 99.7 % | 0.00 | 0.5 % |
| 143207 | 30.4-79.9 | 49.4 s | 32.0 | 99.8 % | 0.00 | 1.8 % |
| 143207 | 149.9-222.7 | 72.8 s | 23.3 | 99.8 % | 0.00 | 3.3 % |
| 144702 | 31.7-82.2 | 50.5 s | 7.6 | 99.7 % | 0.00 | 2.4 % |

- otwpnts 는 87~100 % 의 사이클에서 **발행되고 있었다** — RViz 로는 회피 중으로
  보인다. 그런데 `[trace]` 의 모드는 전부 `trailing` 이다.
- 5b59743 의 게이트가 `evasion_valid && !used_trailing` 이라 닫혔다.
- 계획 프로파일 머리는 82~100 % 가 `anchor0` — vx=0 이 **딱 한 점**이고
  0.1 m 뒤부터 0.62 -> 1.0 -> 1.5 로 올라간다. 즉 세우려는 계획이 아니다.
  경로를 따라 0.25 m 앞의 값은 중앙 **1.25~1.40 m/s**.
- 결정적으로 그 사이클의 88.7 % / 99.7 % 에서 `trailing_retry_clamp_raised` 가
  올랐다 = `allow_stop=false` = **플래너가 "서지 말고 감속"이라고 명시**했는데
  ApplySpeedProfile 의 0 앵커가 그걸 매 사이클 0 으로 덮어썼다.

### 수정

게이트 기준을 "trailing 인가"에서 **"세울 의도인가"**로 바꾼다.

```
evade_msg.data = evasion_valid && (!used_trailing || trailing_no_stop)
                                    // trailing_no_stop = used_trailing && !allow_stop
```

진짜 정지 계획(동적 상대 뒤, 달리다 멈춘 상대, 비상정지 합성 장애물)은
`allow_stop=true` 라 종전대로 닫힌다.

## 2. 벽 오인지 — 부분 해결

**벽 위 유령은 사라졌다. 벽에서 0.25~0.40 m 밴드의 유령은 남아 있고, 지금은
그쪽이 시간을 먹는다.**

해결된 것 (필터가 설정대로 정확히 동작):

| | detector `/perception/obstacles` | planner `/perception/obstacles_frenet` |
|---|---|---|
| 143207 | 벽거리 <0.15 = 1.9 %, p5 0.25 | **<0.15 = 0.0 %**, p5 0.30 |
| 144702 | 벽거리 <0.15 = 1.6 %, p5 0.22 | **<0.15 = 0.0 %**, p5 0.25 |

남은 것:
- 수명 <1 s 트랙의 벽거리 중앙 **0.28~0.31 m**, 수명 >=1 s 는 **0.57~0.91 m**.
  전형적인 유령 서명이다. 트랙 수 기준 24 % (143207 주행구간) / 53 % (144702).
- 가장 뚜렷한 한 건: 144702 `id=27` — 수명 7.0 s, 벽거리 정확히 0.25 m
  (= 필터 컷오프), 이동 0.03 m, 가시 58 %. 벽에 붙어 깜빡이는 고정 유령.
- **주행 랩의 감속 7 구간이 전부** 벽거리 0.25~0.32 m 트랙을 하나 이상 끼고
  있었고, 그중 4 건은 미가시(hold) 트랙이었다. 최장 6.2 s 동안 명령 0.28 m/s.

다음 수정 후보 (근거만 남기고 손대지 않음):
- 벽에 가까울수록 **미가시(hold) 비율이 올라간다**:
  벽거리 <0.30 m 에서 65~79 %, >0.55 m 에서 20~24 %.
  즉 남은 벽 유령의 대부분은 `bridge/visible_static_hold_sec: 0.75` 가
  0.75 s 동안 되살려 놓은 것이다. 밴드별로 hold 를 끄거나 줄이는 것이
  전역 임계값(0.30 -> 0.35)을 올리는 것보다 정밀하다 — 임계값을 올리면
  최협부 1.09 m 구간의 **진짜** 콘을 지운다 (real_car.yaml 주석).

## 3. 이 두 백의 다른 관찰

- 143207 t=32~66 은 장애물 없는 정지인데 teleop 가 30 Hz 로 흐른다 = 수동 대기.
  정지 통계에서 이 구간은 "경로없음 70 %" 로 나온다.
- 144702 의 자차는 s=7.6 에서 d=-1.41 (우측 경계 0.18 m 앞) 에 서 있었다.
  장애물은 d[-0.81,-0.30] 이라 횡으로 완전히 비켜 있는데도 50.5 s 를 못 나갔다.
